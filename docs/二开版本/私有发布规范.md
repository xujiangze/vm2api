# 私有发布规范（二开 fork）

本仓库是 [dofastted/vm2api](https://github.com/dofastted/vm2api) 的二次开发 fork（`xujiangze/vm2api`）。本文件规定私有镜像的构建、命名、发布与可见性规范。升级操作步骤见[升级手册](./升级手册.md)，每个私有版本的改动清单见[私有发布日志](./私有发布日志.md)。

## 分支模型

| 分支 | 角色 | 规则 |
|---|---|---|
| `main` | 上游同步分支 | 保持与上游 dofastted/vm2api 一致，**不放任何私有提交**；定期同步 |
| `xjz` | 私有二开分支，**唯一发布源** | 所有私有改动落在这里；每次同步上游后 `git merge main` 进来，解决冲突后发布新镜像 |

判断"私有提交"的方法：`git log --oneline origin/main..xjz`。该列表里的每一个提交都必须登记进[私有发布日志](./私有发布日志.md)。

## 镜像仓库

- **仓库**：`ghcr.io/xujiangze/vm2api`（GitHub Container Registry，复用 GitHub 账号，无需另注册）
- **可见性**：public（服务器匿名可拉；如改回 private，服务器需 `docker login ghcr.io`）
- **凭证**：GitHub PAT（classic，勾 `write:packages`），登录方式：
  ```bash
  echo $GITHUB_CR_PAT | docker login ghcr.io -u xujiangze --password-stdin
  ```

## 构建方案

上游镜像由 `.github/workflows/release.yml` 在打 `v*` tag 时构建并推到 `ghcr.io/<owner>/vm2api`（镜像名按 `github.repository_owner` 动态生成）。**私有发布不走 CI，在开发机（Apple Silicon Mac）手工构建**：

```bash
docker buildx build \
  --platform linux/amd64 \
  -t ghcr.io/xujiangze/vm2api:v{版本} \
  --push .
```

说明：

- 根目录 `Dockerfile` 的 web / helpers / payload 三个阶段都标了 `--platform=$BUILDPLATFORM`，在 arm64 Mac 上**原生执行**，只有最终运行层走 amd64 模拟，整体构建速度可接受。
- 镜像内的槽位二进制（kin-kernel / kin-codex-kernel 等）由 `deploy/payload.json` 锁定，从**上游公开 GitHub Release** 下载并做 sha256 校验，不需要上游账号。上游删资产会导致构建失败，届时需同步上游新的 `deploy/payload.json`。
- 线上若出现 ARM 服务器（`uname -m` = `aarch64`），不能直接用根 Dockerfile（其中 helpers 阶段硬编码 `GOARCH=amd64`），需参照上游 CI 的 `deploy/Dockerfile.arm64-control` 单独构建。

## Tag 规范

- 格式：**`v{上游VERSION}-xjz.{序号}`**，例：`v1.4.061-xjz.1`
- 上游 `VERSION` 文件推进后，序号从 1 重新计数
- 禁止发布**无后缀** tag（与上游镜像同名，无法区分来源）；不使用 `latest`（避免线上意外升级）

## 发布 checklist

1. `xjz` 分支工作区干净，私有提交已推送（`git status` / `git log origin/main..xjz`）
2. `npm run test:unit` 通过（本机已知 `kernel-install-writer-locks.test.mjs` 会挂起，属环境问题，可跳过）
3. 构建并推送（上面的 buildx 命令，tag 按规范）
4. 验证匿名可拉（确认可见性没被改回私有）：
   ```bash
   curl -s -o /dev/null -w "%{http_code}\n" https://ghcr.io/v2/xujiangze/vm2api/manifests/{tag}
   # 200=公开可拉；401=私有，需先设 public
   ```
5. 在[私有发布日志](./私有发布日志.md)登记新版本（含 digest）
6. 线上按[升级手册](./升级手册.md)执行
